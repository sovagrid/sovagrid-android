# SovaGrid для Android

Нативное приложение на Kotlin для прямого SSH-доступа к серверам и просмотра метрик SovaGrid Hub. Текущие исходники приложения с версией `0.6.0` устанавливают серверный пакет `v0.10.0-preview`; в версии `0.5.1` добавлено отображение DNS-проверок к нативному мониторингу HTTP/HTTPS и TCP. Код Hub и SSH вынесен в отдельные классы; SSH-клиент также выделен в JVM-модуль `ssh-core`.

## Возможности

- Список SSH-серверов: название, адрес, порт, пользователь и необязательный промежуточный SSH-хост (аналог `ProxyJump`).
- Интерактивный VT-терминал для SSH-сессии через SSHJ `0.41.1`. Экран работает на встроенном [xterm.js 6.0.0](app/src/main/assets/terminal/vendor/xterm/LICENSE) и [fit addon 0.11.0](app/src/main/assets/terminal/vendor/fit/LICENSE) (MIT): цвет, управление курсором, альтернативный экран для `vim` и других TUI-приложений, прокрутка последних 2000 строк. Скрипты и шрифты не загружаются из сети; терминальный WebView разрешает только ресурсы приложения. Учётные данные SSH не передаются в WebView.
- SSH-серверу выделяется PTY `xterm-256color` с реальными размерами экрана. При повороте телефона и изменении видимой области приложение посылает SSH `window-change`; поворот не рвёт соединение. При уходе приложения в фон сессия закрывается.
- В терминале можно вводить текст с экранной или аппаратной клавиатуры; есть отдельные Esc, Tab, стрелки, Enter, Ctrl+C/D/Z, одноразовая клавиша Ctrl для следующей буквы и кнопка вставки из буфера. Многострочная вставка требует подтверждения. Нижнее поле отправляет команду с Enter.
- На главном экране есть переключатель темы: системная (по умолчанию), светлая или тёмная. Выбор сохраняется между запусками и применяется к нативным экранам и локальному VT-терминалу. WebView передаёт странице панели соответствующее `prefers-color-scheme`; фактические цвета удалённой панели задаёт сам веб-клиент. Для смены темы во время SSH-сессии вернитесь к списку серверов; открытая SSH-сессия при этом завершится.
- Аутентификация SSH-паролем, сохранённым ключом SovaGrid или приватным ключом из системного выбора файлов (с необязательной парольной фразой).
- «SSH-ключи: создать / публичный ключ» доступно на главном экране без добавленного сервера и SSH-входа. Укажите название — приложение создаст пару Ed25519. Публичная строка OpenSSH с комментарием доступна через отдельные кнопки «Копировать публичный ключ» и «Сохранить публичный .pub»; системный выбор места сохраняет расширение `.pub` без добавления `.txt`; её можно затем добавить в `~/.ssh/authorized_keys` нужного пользователя на сервере. Приватная часть не показывается, не экспортируется и не меняет сервер автоматически. Для терминала, панели и SFTP выберите «Мои ключи SovaGrid / создать новый» вместо импорта файла. Если вы создали ключ из выбора профиля, нажмите «Использовать для подключения» прямо в окне открытого ключа. Ключи для конечного и промежуточного серверов выбираются отдельно; общий ключ используется только если вы сами выбрали его в обоих полях. При удалении ключа приложение перечислит профили и направления, для которых вы его выбирали, и запросит отдельное подтверждение. На сервере публичная часть автоматически не удаляется.
- Кнопка «Файлы через SFTP» у каждого сохранённого SSH-сервера открывает нативный файловый экран. При первом входе ключ сервера можно получить и сравнить с независимым источником прямо здесь: до подтверждения серверу не отправляются данные входа. Для ProxyJump сначала подтверждается ключ промежуточного узла; затем приложение запрашивает данные промежуточного узла, проверяет его сохранённый ключ и получает ключ конечного сервера без отправки данных конечного входа. При каждом файловом входе оба ключа проверяются повторно. Каталоги можно открывать, подниматься к родительскому и переходить к указанному абсолютному пути; отдельные файлы скачиваются через системный выбор места, а локальные документы загружаются через системный выбор файла. Бинарные байты передаются без кодирования в текст. Передача не перезаписывает существующий удалённый файл, временный файл загрузки создаётся с правами `0600` и переименовывается после полной передачи. При отмене SFTP отключается; неполный удалённый файл удаляется, если сервер ещё доступен. Скачивание сначала идёт в приватный временный файл приложения, затем в выбранный документ; при ошибке выбранный документ удаляется, если это позволяет провайдер Android. После перехода приложения в фон SSH-соединение закрывается; при выборе файла системное окно может держать соединение не дольше двух минут. Ссылки и специальные файлы в этом экране не открываются.
- При первом соединении приложение получает ключ сервера **без передачи учётных данных** и показывает SHA-256 fingerprint. Подключение разрешается после подтверждения пользователем. При изменении сохранённого ключа вход блокируется. Сброс доверия требует отдельного подтверждения.
- Для маршрута через промежуточный хост ключи промежуточного и конечного серверов подтверждаются и сохраняются отдельно. Пароль или приватный ключ для каждого SSH-входа вводится отдельно. Промежуточный сервер открывает канал `direct-tcpip` к указанному пользователем адресу; например `127.0.0.1:2200` означает loopback **на промежуточном узле**, если там настроен такой порт.
- Полная веб-панель открывается на телефоне через сохранённый SSH-хост: приложение создаёт локальный порт `127.0.0.1`, пробрасывает его на `127.0.0.1:8766` выбранного узла и загружает `/sovagrid/monitoring/` в WebView. Для профиля с ProxyJump можно выбрать Hub на промежуточном либо конечном узле. Каждый SSH-узел требует отдельной проверки ключа и своих учётных данных; каналы закрываются вместе с панелью. На управляемом Hub вход через root или `sudo -n` создаёт одноразовый SSH-грант и открывает панель без второго пароля; на старых версиях остаётся обычная форма входа.
- После открытия панели кнопка «Получить начальный пароль Hub» читает `/etc/sovagrid/admin-password` через **уже проверенное SSH-соединение**. Работает, если SSH-пользователь имеет право чтения файла (обычно `root`); повторно вводить ключ или пароль SSH не нужно. Пароль показан маской, копируется только по отдельному нажатию и не сохраняется приложением. Буфер обмена очищается через 60 секунд или при закрытии экрана/переходе в фон. После смены пароля Hub в «Настройках» исходный файл содержит устаревший пароль.
- В панели можно запросить защищённую выдачу профиля WireGuard. После расшифровки в WebView кнопка «Скачать .conf» передаёт файл нативному мосту только по нажатию; Android открывает системный выбор места сохранения. Мост принимает сообщения только от основного документа на точном локальном порту активного SSH-туннеля, проверяет имя и каноническую кодировку профиля. При открытии системного выбора файла туннель закрывается; после сохранения или отмены экран панели закрывается. Нативная копия профиля не пишется во временный файл приложения и очищается из памяти после записи.
- В разделе Telegram полной панели ссылки «Открыть BotFather» и «Открыть бота» открывают Telegram или браузер на телефоне после нажатия. Приложение принимает только точные HTTPS-ссылки `t.me/BotFather` и `t.me/<имя_бота>` без дополнительных путей и параметров. Остальные внешние ссылки и загрузки WebView блокируются. При переходе в Telegram приложение закрывает SSH-туннель, поэтому для возвращения в панель потребуется снова подключиться.
- Вход в Hub по HTTPS с логином и паролем; имя и роль текущего пользователя, список серверов, состояние связи, CPU, RAM, диск, uptime; ручное обновление и выход. Нативная вкладка «Проверки» показывает состояния HTTP/HTTPS, TCP и DNS, последние результаты и время получения без адресов целей или DNS-ответов. Вкладка «Службы» даёт администратору точную проверку `.service` и подтверждаемые start/stop/restart через структурированный Hub API. Она повторно проверяет права, доступность Agent и состояние конкретной службы перед изменением. Действия для SSH, сети, VPN, Docker и SovaGrid доступны только как status; Hub и root broker проверяют ограничения независимо. После изменения или неопределённого результата нужно заново запросить status. Вкладка событий показывает активные тревоги и историю восстановления, включая инциденты сетевых проверок. Наблюдатель (`viewer`) видит мониторинг, а оператор и администратор (`operator` / `admin`) также могут подтверждать тревоги после отдельного подтверждения. Перед обновлением, загрузкой проверок и подтверждением приложение заново проверяет владельца и роль сеанса через Hub. Управление пользователями и настройка целей остаются в полной веб-панели.
- Вкладка «Контейнеры» показывает ограниченный инвентарь Docker. Для незащищённого контейнера из полного списка администратор может запросить статус, затем подтвердить start/stop/restart по полному 64-символьному ID. Перед отправкой приложение повторно загружает инвентарь и сверяет доказательство статуса; Hub и Agent независимо проверяют свежесть, точный ID и локальную root-политику. Защищённые контейнеры показываются только для просмотра состояния из инвентаря, а Podman не управляется. Неопределённый исход требует новой проверки, автоматического повтора действия нет.

Все отметки Hub и Agent разбираются как UTC Unix seconds. Только при отображении они переводятся в часовой пояс устройства с явным смещением UTC. Экран сервера отдельно показывает часовую зону и состояние NTP сервера; `rtc_offset_seconds` подписан как разница RTC и системных часов, без автоматической коррекции времени и без заявления о точном отклонении от UTC.

## Сборка и запуск

Откройте эту папку в Android Studio. Требуются JDK 17 или новее, Android SDK Platform 36 и Android SDK Build Tools. Gradle Wrapper `8.13`, Android Gradle Plugin `8.13.2` и Kotlin `2.2.20` уже заданы в проекте. Зависимости и SDK при первом запуске могут скачиваться.

Команда из корня проекта:

```sh
./gradlew :ssh-core:test :app:testDebugUnitTest :app:assembleDebug
```

Отдельный тест SFTP поднимает одноразовый локальный `sshd` и проверяет двоичную загрузку и скачивание, пустой файл, отмену, запрет перезаписи и блокировку подменённого ключа:

```sh
scripts/test-sftp-local.sh
```

При необходимости задайте `ANDROID_HOME` или путь к SDK в локальном `local.properties` (`sdk.dir=...`). Файл `local.properties`, каталоги `.gradle/` и `build/` исключены из Git. Нативное сохранение `.conf` проверено на изолированном Android API 36 эмуляторе: тестовая страница прошла через локальный SSH-проброс, системный выбор сохранил файл с ожидаемым SHA-256, а неверное имя файла и сообщение из iframe были отклонены. На том же локальном SSH-хосте экран терминала успешно выполнил команду `pwd`. Чтение начального пароля проверено на локальном SSH-сервере с тестовым ответом и с отказом команды.

Отдельный локальный тест проверяет начальные размеры PTY, изменение размера и отправку сырой клавиши Esc:

```sh
scripts/test-terminal-local.sh
```

На Android API 36 ARM-эмуляторе приложение подключилось к одноразовому локальному `sshd` после сверки ключа. Через DevTools **debug-сборки** проверены размер экрана 41×33, ответ `stty size`, цветная VT-последовательность, альтернативный экран `vim` и изменение размера до 97×6 при повороте без сброса соединения. Отладка WebView доступна только в debuggable-сборке.

Для маршрута панели через промежуточный узел есть воспроизводимый двухузловой тест на локальном `sshd`:

```sh
scripts/test-panel-jump-local.sh
```

Скрипт поднимает два временных SSH-сервера с разными ключами хостов и пользователей, локальную HTTP-страницу на `127.0.0.1:8766` и проверяет панель, чтение тестового начального пароля и блокировку подмены ключа на любом узле. Нужны `sshd`, `ssh-keygen`, Python 3, `curl` и свободный порт 8766. Тестовые ключи и серверы удаляются после проверки.

Сборка создаёт `app/build/outputs/apk/debug/app-debug.apk`. Файл `../sovagrid-android-debug.apk` сохранён как прежняя **debug-сборка 0.3.2**; APK из текущих исходников `0.6.0` создаётся в каталоге сборки проекта. В CI собираются подписанные preview debug- и release-сборки; [опубликованный APK 0.6.0](https://github.com/sovagrid/sovagrid-android/releases/tag/v0.6.0-preview) собран из release-варианта без `debuggable` и подписан тем же постоянным preview-сертификатом, что 0.5.0. Публикация в магазине ещё не выполнялась. Начиная с `0.3.3` применяется постоянная preview-подпись, описанная ниже. При заданных `SOVAGRID_TEST_SSH_HOST`, `SOVAGRID_TEST_SSH_USER`, `SOVAGRID_TEST_SSH_KEY_PATH` JVM-тесты проверяют реальный SSH-переход, блокировку изменённого ключа и доступ к панели через проброс на промежуточном узле. Сборка и lint проходят в CI. На Android API 36 ARM-эмуляторе проверены запуск 0.5.0, темы, создание ключа и открытие панели через локальный тестовый SSH-туннель. При обновлении до 0.5.1 тот же ключ сохранился и прошёл новый SSH-вход на локальный тестовый хост.

Отдельный необязательный JVM-тест `VerifiedJumpIntegrationTest` проверяет реальный маршрут к заданному вами SSH-серверу через промежуточный узел. Для запуска задайте переменные `SOVAGRID_TEST_JUMP_HOST`, `SOVAGRID_TEST_JUMP_PORT`, `SOVAGRID_TEST_JUMP_USER`, `SOVAGRID_TEST_JUMP_KEY_PATH`, `SOVAGRID_TEST_JUMP_FINGERPRINT` и соответствующие `SOVAGRID_TEST_TARGET_HOST`, `SOVAGRID_TEST_TARGET_PORT`, `SOVAGRID_TEST_TARGET_USER`, `SOVAGRID_TEST_TARGET_KEY_PATH`, `SOVAGRID_TEST_TARGET_FINGERPRINT`. Отпечатки получите через независимый доверенный канал. Ключи и пароли в репозиторий не добавляются; если переменные не заданы, тест пропускается.

## Подпись предварительных Android-сборок

Начиная с `0.3.3` опубликованные предварительные APK используют постоянный сертификат SovaGrid с SHA-256:

```text
00d6710507a15f068dd536bf7e0d60d3674317136d13d8abea6d15cd67c6d11d
```

Обновляйте приложение установкой новой версии поверх прежней: это сохраняет данные приложения и доступ к Android Keystore. Переход с `0.3.2`, подписанной одноразовым debug-сертификатом CI, требует разовой переустановки; версия `0.3.2` ещё не сохраняла созданные устройством приватные SSH-ключи. После создания ключей в `0.3.3` удаление приложения приведёт к их потере.

Для main/ручных сборок CI требуются repo secrets `SOVAGRID_ANDROID_PREVIEW_KEYSTORE_B64` и `SOVAGRID_ANDROID_PREVIEW_STORE_PASSWORD`; временный PKCS12-файл получает права `0600` и удаляется после сборки. Gradle получает путь и пароль через `SOVAGRID_ANDROID_SIGNING_STORE_FILE` / `SOVAGRID_ANDROID_SIGNING_PASSWORD`, alias — `sovagrid-preview`. Перед загрузкой APK workflow проверяет сертификат. Pull request выполняет тесты/lint/локальную debug-сборку без этих секретов и не загружает APK. Локальная сборка без signing env также использует обычный локальный debug-сертификат.

Генерация и OpenSSH-совместимость, политика ссылок и защита AES-GCM проверяются JVM-тестами. Device-only runner `org.sovagrid.android.SshKeyVaultInstrumentation` в отдельном test APK проверяет Android Keystore, права `0600/0700`, отказ при подмене AAD, отсутствие автоматической замены, удаление, публичное копирование без SSH-входа и сохранность ключа после обновления APK с тем же сертификатом. Режим `public-save-ui` прошёл на Android API 36: настоящая кнопка открыла системный DocumentsUI, файл в Downloads получил ровно расширение `.pub`, а байты совпали с публичной строкой OpenSSH и завершающим переводом строки. Тест удаляет только свой ключ и файл с уникальным именем. Проверены также обновление `0.3.3` → `0.3.4` поверх установленной версии и доступность созданного до обновления ключа. В приложение test runner не включается; команд и точек экспорта приватного ключа в нём нет.

## Как подключить SSH-сервер

1. Добавьте адрес, порт и имя пользователя.
2. Откройте сервер и сравните показанный SHA-256 fingerprint с ключом, полученным от сервера по независимому каналу. Для Ubuntu его можно вывести на самом сервере командой `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256` (или для того типа ключа, который показало приложение).
3. Подтвердите совпадение. Выберите пароль или приватный ключ и подключитесь.
4. Коснитесь терминального экрана для ввода с клавиатуры или введите команду в нижнее поле. Панель клавиш прокручивается горизонтально. Кнопка «Отключиться» закрывает SSH-сессию; переход к списку серверов и уход приложения в фон тоже закрывают её.

Для маршрута через обратный SSH-туннель при добавлении сервера выберите «Через промежуточный SSH-хост». Укажите конечный адрес `127.0.0.1`, порт, выделенный вашим туннелем, и пользователя целевого сервера; для промежуточного узла укажите его публичный адрес, SSH-порт и пользователя. Сначала подтвердите ключ промежуточного узла, затем его учётные данные и ключ целевого сервера. Если обратный туннель временно не работает, приложение покажет ошибку подключения; профиль сохранится для повторной попытки.

Чтобы открыть панель Hub с телефона без публичного HTTPS-порта, добавьте сервер как SSH-профиль и нажмите «Открыть панель через SSH». Для профиля с промежуточным узлом выберите Hub на промежуточном либо конечном сервере. Приложение отдельно проверит SSH-ключ каждого узла и запросит его учётные данные; панель откроет `/sovagrid/monitoring/` на `127.0.0.1:8766` выбранного сервера. Hub на конечном узле должен работать на своём loopback-порту. На экране можно получить начальный пароль Hub с выбранного узла либо войти уже заданным паролем. WebView загружает панель только с временного локального порта; внешние ссылки открываются системным обработчиком после нажатия. Для нативного сохранения профиля требуется AndroidX WebKit `WEB_MESSAGE_LISTENER`.

Перед открытием панели приложение проверяет состояние выбранного узла фиксированной командой через уже подтверждённый SSH-канал. Оно различает управляемый Hub, отдельный Agent, чистый Ubuntu-сервер, конфликтующие файлы и неподдерживаемую ОС. Статус «чистый сервер» принимается только от root или пользователя с `sudo -n`; неопределённый ответ не разрешает установку и не мешает открытию уже работающей панели. Для чистого сервера при входе `root` приложение предлагает установку прямо с телефона после отдельного подтверждения. Сервер загружает ровно пакет релиза `v0.10.0-preview` по HTTPS, сверяет встроенный SHA-256 пакета и манифеста, повторяет проверку пустого Ubuntu-сервера и запускает `run.sh`. Ход установки показан в приложении. Установка работает как отдельное задание systemd: при уходе телефона в фон оно продолжается на сервере, а после нового SSH-входа приложение читает закрытое состояние и возвращается к прогрессу. После успешной проверки Hub открывается через SSH-туннель. Серверу требуется доступ к GitHub и одна из программ `curl`, `wget` или `python3`; при отсутствии доступа подготовьте пакет по инструкции Blueprint и установите его с доверенного компьютера. Вход через `sudo -n` подходит для чтения состояния, но первая установка из телефона требует `root`. Если серверная установка завершится с ошибкой, её состояние сохранится; приложение не повторит её поверх существующих файлов. Сначала проверьте сервер. На узле с отдельным Agent, полная установка не предлагается, чтобы сохранить существующие ключи и обратный туннель. Если одноразовый SSH-вход временно не сработал, кнопка «Войти через SSH» запрашивает новый грант в том же проверенном соединении; обычная форма входа остаётся доступной. Одноразовый грант передаётся только в JavaScript проверенного локального WebView и погашается POST-запросом; в URL, буфер обмена и настройки он не попадает.

Пароль SSH и парольная фраза ключа не сохраняются и стираются из полей ввода после начала подключения. Адреса и **публичные** ключи серверов сохраняются в `SharedPreferences`; запись подтверждённого ключа происходит до SSH-аутентификации. Импортированный файл приватного ключа читается только для текущего подключения. Для созданных в SovaGrid ключей 32-байтовый Ed25519 seed хранится как AES-256-GCM ciphertext в `noBackupFilesDir`, с обёрточным ключом в [Android Keystore](https://developer.android.com/privacy-and-security/keystore). AAD связывает ciphertext с UUID, версией формата, названием, временем создания и публичной частью. Повреждение файла, потеря обёрточного ключа или ошибка расшифровки блокируют вход без генерации замены. OpenSSH private key создаётся только в памяти для существующего пути SSHJ через [штатный encoder Bouncy Castle](https://github.com/bcgit/bc-java/blob/r1rv84/core/src/main/java/org/bouncycastle/crypto/util/OpenSSHPrivateKeyUtil.java). Резервное копирование и перенос приватных ключей на другое устройство не реализованы; удаление приложения стирает эти ключи. Начальный пароль Hub читается фиксированной командой `head -c 257 /etc/sovagrid/admin-password` через SSH; её ответ ограничен по времени и размеру, проверяется как URL-safe пароль, не пишется в файл или журнал и очищается из памяти диалога при закрытии. Токен Hub остаётся в памяти до выхода из аккаунта или закрытия экрана. Резервное копирование данных приложения отключено, снимки экранов приложения запрещены.

Терминал хранит до 2000 строк истории и замедляет чтение SSH, если экран не успевает отобразить быстрый вывод; произвольного ограничения по длительности сессии нет. В нативном SFTP-экране доступен один файл за операцию; массовая передача каталогов и работа с символьными ссылками пока не реализованы. Скачивание временно требует на телефоне место, равное размеру файла.

## Hub API

В приложении укажите HTTPS-адрес Hub без пути, например `https://hub.example.com`. HTTP и перенаправления для запросов авторизации не допускаются. Используется системная проверка TLS-сертификата Android.

```text
POST /api/v1/session
{"username":"...","password":"..."}
→ {"token":"...","expires_at":2000000000,"user":{"id":"...",
   "username":"operator","role":"operator","enabled":true,"revision":1,
   "created_at":1900000000,"updated_at":1900000000}}

GET /api/v1/session
Authorization: Bearer <token>
→ {"expires_at":2000000000,"user":{...}}

GET /api/v1/servers
Authorization: Bearer <token>
→ {"servers":[{"id":"...","name":"...","online":true,
                "last_seen":1900000000,"latest":{"collected_at":1900000000,
                "cpu_percent":10.5,"memory_percent":42.0,
                "disk_percent":56.0,"uptime_seconds":3600,
                "details":{"clock":{"system_utc_epoch":1900000000,
                  "timezone":"Europe/Moscow","ntp_synchronized":true,
                  "rtc_local_time":false,"rtc_utc_epoch":1900000165,
                  "rtc_offset_seconds":165}}}}]}

GET /api/v1/servers/{id}/checks
Authorization: Bearer <token>
→ {"server_id":"...","revision":1,"worker_seen_at":1900000000,
   "checks":[{"id":"...","name":"Сайт","kind":"http","enabled":true,
              "interval_seconds":60,"timeout_seconds":5,"state":"up",
              "latest":{"observed_at":1900000000,"received_at":1900000001,
                        "status":"up","latency_ms":42,"http_status":200,
                        "tls_expires_at":1901000000,"error_code":null}}]}

GET /api/v1/incidents
Authorization: Bearer <token>
→ {"incidents":[{"kind":"check:<check_id>","subject":"Сайт",
                 "state":"resolved","opened_at":1900000000,
                 "updated_at":1900000090,"resolved_at":1900000090,...}]}

DELETE /api/v1/session
Authorization: Bearer <token>
→ отзывает текущий токен
```

Имя, роль и токен Hub существуют только в памяти активного экрана: приложение не сохраняет их в настройки, файлы или состояние Activity. Если поле `user` в ответе входа присутствует, обязательные поля и их типы проверяются строго; неизвестная роль, отключённая учётная запись и неподтверждённая identity не получают доступ. Для старых версий Hub без поля `user` при входе сохраняется совместимость с единственным администратором; только в этом режиме отдельная проверка `GET /session` не требуется. Ответ HTTP 401/403 или изменение владельца/роли очищает сеанс и возвращает экран входа с пояснением. Ошибка сети оставляет экран для повторного обновления.

Выход из Hub сразу удаляет локальный токен из состояния приложения и отправляет фоновый запрос на его отзыв. Если запрос не дошёл до Hub, токен перестанет работать после истечения срока действия (8 часов по текущей конфигурации). При закрытии приложения без явного выхода серверная сессия также действует до истечения срока. Настройка Telegram доступна через полную веб-панель, открываемую по SSH; в отдельном нативном экране Hub доступны обзор метрик, проверки доступности, дисковые тревоги по точкам монтирования и inode, системные службы, Docker-контейнеры и события с ролевым подтверждением тревог. Правила дисковых тревог меняет только администратор; приложение сверяет ревизию и после неясного ответа читает состояние заново без повторной отправки. Нативные действия со службами и контейнерами требуют отдельно включённых на Agent root broker и локальной политики; приложение не включает их автоматически и не запускает команды через shell.

## Структура

- `app/` — Android UI, локальное хранилище адресов и ключей, HTTPS-клиент Hub.
- `ssh-core/` — SSH, проверка ключа сервера и тесты политики доверия.

Не добавляйте пароли, приватные ключи, файлы `local.properties` или содержимое `build/` в репозиторий.
